# Styling Audit Analysis Report

This document details the scan and audit of the InvoicingApplication codebase to identify unnecessary custom styling, such as non-native shadows, custom hover effects (`.onHover`), and custom selection highlights that interfere with standard macOS native UI behaviors.

## Summary of Core Findings
1. **Sidebar Selection Text Color Issue**: In `SidebarItemRow.swift`, the selected row overrides its text/icon foreground style to a hardcoded accent/primary color (`StyleGuide.Colors.primary`) instead of allowing standard system text color inversion. This results in poor legibility (accent text on accent background) when selected under native macOS sidebar highlighting.
2. **Ubiquitous Custom Hover Scaling**: Multiple views scale up elements on hover (e.g. `RelationshipsLayouts.swift` and `ServiceAssignmentSheetView.swift` scale cards by 1.01x to 1.02x, and `ServiceTemplateDeleteButton` by 1.15x). Standard macOS controls do not scale elements on hover; this behaves like an iOS or web app design rather than a native macOS App.
3. **Heavy Custom Drop Shadows**: Views like `MonthView`, `WeekView`, and `EnhancedGroupBoxStyle` apply custom, heavy drop shadows that float flat content above the window. This diverges from macOS's native flat, subtle card styles and clean interfaces.
4. **Custom Canvas Design Tools**: While custom canvas shadows, drop highlights, and hover handles in `Feature.InvoiceTemplateEditor` are essential domain features of the template designer, the editor's chrome (headers, buttons, popovers) uses custom hover/selection modifiers that should be standard native controls.
